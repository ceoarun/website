VAPT Experience & Selected Projects

Infrastructure VAPT — Enterprise DMZ & Internal Services

Scope: Public DMZ, management panels, SSH/RDP hosts, firewall rules and internal management networks

Duration: 3 weeks

Detailed Approach

I started with wide-scope discovery — using Masscan for high-speed port inventory and Nmap for service/version detection. Findings were enriched with banner grabs and HTTP/HTML analysis to discover management endpoints.

In-depth Testing Steps

  1. Discovery & fingerprinting: Masscan & Nmap, followed by targeted NSE scripts and banner analysis to identify outdated services.
  2. Configuration review: SSH banners, weak ciphers, RDP network-level auth settings and exposed management panels (default credentials, forgotten interfaces).
  3. Firewall & ACL validation: Verified rule sets by attempting allowed/blocked flows from controlled jump hosts and validated egress policies to identify exfil channels.
  4. Patch & CVE correlation: Used Nessus/OpenVAS and manual version checking to map CVEs and determine exploitability in-scope.
  5. Controlled validation: Where allowed, safe Metasploit checks or manual exploit validation in a labed environment to confirm impact without causing disruption.

Key Findings & Impact

Detected exposed management panels with default or weak access, SSH using deprecated ciphers and several hosts missing critical OS updates. These exposures could allow remote compromise or provide an attacker with a foothold for lateral movement.

Tools & Deliverables

Primary tools: Masscan, Nmap, Nessus/OpenVAS, Metasploit (lab validation), tcpdump/Wireshark. Delivered: technical PoC (screenshots, commands), prioritized remediation list and ACL change playbook.

Web Application VAPT — Multi-tenant SaaS Portal

Scope: Frontend, APIs, authentication flows, multi-tenant authorization, and business logic

Duration: 4 weeks

Detailed Approach

I combined automated scanning (Burp Scanner, ZAP) with heavy manual testing. Focus was on authenticated flows, API parameter tampering, and business logic abuse which automated scanners often miss.

In-depth Testing Steps

  1. Session/auth testing: Reviewed session token entropy, storage, rotation and logout flows. Tested CSRF protections and cookie flags.
  2. Parameter tampering & IDOR: Fuzzed object IDs and endpoints via Burp Intruder and custom Python scripts to find unauthorized access across tenants.
  3. Input validation: Manual XSS and injection testing in different contexts (HTML body, attributes, JSON responses). Used custom payloads to bypass WAFs when necessary for proof-of-concept.
  4. Business logic: Created attack scenarios that abuse order/workflow flows (e.g., privilege escalation via workflow state transitions).
  5. API & rate limiting: Checked for unauthenticated or excessive-access tokens, rate-limit bypass and parameter pollution.

Key Findings & Impact

Found high-impact IDOR allowing cross-tenant data access and several auth weaknesses in token handling. These issues were prioritised and remediations included strict object ownership checks, token invalidation policies and improved CSP/CORS headers.

Tools & Deliverables

Primary tools: Burp Suite Pro, OWASP ZAP, ffuf, sqlmap, Postman. Delivered: PoC scripts (curl/Postman), remediation code snippets, CVSS-based prioritisation and retest validation.

Mobile Application VAPT — Android

Scope: Binary analysis, API backend, insecure storage, SSL pinning and IPC

Duration: 2–3 weeks

Detailed Approach

Started with static analysis (jadx, apktool) to identify hardcoded URLs, keys and insecure patterns. Followed by dynamic runtime checks using Frida and proxying network traffic through Burp/mitmproxy to validate API security.

In-depth Testing Steps

  1. Static review: Decompiled APKs to review logic, find hardcoded secrets and insecure serialization/deserialization.
  2. Dynamic testing: Used Frida/Objection for runtime hooks, bypasses and sensitive API parameter inspection.
  3. Transport security: Intercepted traffic to check TLS configuration and attempted SSL pinning bypasses in a safe, controlled manner.
  4. Storage & credential checks: Looked for insecure use of SharedPreferences/Keychain and suggested secure alternatives (Android Keystore, iOS Keychain).

Key Findings & Impact

Found insecure local storage and predictable tokens on certain flows. Recommended token rotation, secure storage mechanisms and hardened TLS certificate validation. Provided Frida scripts (redacted/safe) to reproduce runtime behaviour.

Tools & Deliverables

Primary tools: jadx, APKTool, Frida, MobSF, mitmproxy, Objection. Delivered: binary analysis notes, Frida scripts (safe PoCs), developer remediation checklist.

API VAPT — Microservices & Gateway

Scope: REST & GraphQL endpoints, JWT handling, service-to-service auth and rate-limiting

Duration: 3 weeks

Detailed Approach

Focus on token validation, audience/issuer checks, and enforcement at the gateway. Combined GraphQL introspection with manual fuzzing and parameter tampering across microservices.

In-depth Testing Steps

  1. JWT analysis: Verified signature validation, issuer/audience claims and expiration handling; tested weak signing keys and algorithm downgrade vectors.
  2. GraphQL & schema fuzzing: Used introspection to find hidden queries and parameters then fuzzed inputs for injection or over-exposure.
  3. Rate-limiting checks: Identified endpoints susceptible to brute-force, scraping or credential stuffing and suggested gateway rules.

Key Findings & Impact

Found weak token validation and missing audience checks that allowed token reuse across services. Recommended strict JWT validation, audience/issuer enforcement and gateway rate-limiting policies.

Tools & Deliverables

Primary tools: Postman, Burp Suite, jq, GraphiQL, jwt.io. Delivered: curl/Postman PoCs, gateway policy examples and threat model updates.
